# SSP Instructor Guide

## Purpose

This guide is for internal use to help run the 9-week Semiconductor Summer Program (SSP). It provides practical guidance on weekly flow, daily execution, facilitation strategies, and contingency plans.

---

# Program Model (Core Philosophy)

The program uses a **layered learning model**:

* **High School (HS)**: conceptual understanding, system thinking, explanation
* **CSUF**: implementation, coding (Verilog), simulation, debugging

Both groups:

* Learn the same concepts
* Work at different depths
* Reconnect weekly

---

# Delivery Structure

## Weekly Rhythm

**Monday (Anchor Lecture – All Students, Zoom, recorded)**

* 45–60 min
* Big picture, system view, motivation

**Midweek (Divergence)**

* HS: async work (2–4 hrs/week)
* CSUF: in-person labs (2–3 sessions/week)

**Friday (Integration – All Students, Zoom)**

* 30–45 min
* HS explains systems
* CSUF demonstrates implementations

---

# Instructor Responsibilities

Each week you produce:

1. **Lecture (recorded + live)**

   * Reusable
   * Focus on intuition + system view

2. **HS Activity Packet (2–3 pages max)**

   * Diagrams
   * Guided questions
   * Short reflection

3. **CSUF Lab Instructions**

   * Step-by-step
   * Testable checkpoints
   * Minimal ambiguity

---

# Weekly Execution Template

## Monday – Lecture (All Students)

**Structure:**

1. Motivation (5–10 min)
2. System-level explanation (20–30 min)
3. Conceptual walkthrough (15–20 min)
4. Bridge to projects (5–10 min)

**Key rule:** Avoid deep math or code here.

---

## HS Track (Async)

**Time: 2–4 hours/week**

Typical flow:

1. Watch short videos (10–20 min chunks)
2. Complete guided worksheet
3. Draw diagrams / explain systems
4. Submit (PDF/image/text)

**Design rules:**

* Visual > text
* Short tasks
* Clear prompts

---

## CSUF Track (In-Person)

**Time: 3–5 hours/week**

Typical session:

1. 10 min recap
2. 60–90 min lab work
3. Checkpoints + debugging

**Design rules:**

* Explicit steps
* Provide starter code
* Include expected outputs

---

## Friday – Integration Session

**Structure:**

1. HS explains system (10–15 min)
2. CSUF demos implementation (10–15 min)
3. Instructor connects concepts (10–15 min)

**Goal:** Reinforce that both tracks are solving the same problem.

# Week-by-Week Instructor Plan

## Week 1 – What Is a Chip?

* Lecture: chips, inputs/outputs
* HS: identify chips in daily life
* CSUF: semiconductor overview

## Week 2 – Logic + Design Flow

* Lecture: logic + chip pipeline
* HS: block diagrams
* CSUF: CMOS + flow intro

## Week 3 – Program → Hardware

* Lecture: how instructions execute
* HS: trace simple programs
* CSUF: datapath overview

## Week 4 – ALU

* HS: operations conceptually
* CSUF: implement ALU in Verilog

## Week 5 – Control (FSM)

* HS: state diagrams
* CSUF: FSM in Verilog

## Week 6 – Integration

* HS: trace execution
* CSUF: combine datapath + control

## Week 7 – Debugging

* HS: identify logic errors
* CSUF: debug processor

## Week 8 – Synthesis + Careers

* HS: big picture + careers
* CSUF: synthesis + tradeoffs

## Week 9 – Presentations

* Joint presentations

---

# Facilitation Tips

## For HS (Virtual)

* Keep tasks short
* Use visuals
* Avoid jargon

## For CSUF

* Expect confusion
* Encourage debugging
* Avoid solving problems for them

---

# Common Failure Points

## 1. HS disengagement

Fix: simplify + shorten tasks

## 2. CSUF stuck debugging

Fix: provide checkpoints + example outputs

## 3. Weak integration sessions

Fix: prepare prompts ahead of time

---

# Contingency Plans

## If CSUF falls behind

* Provide partial solutions
* Focus on key components only

## If HS struggles

* Reduce workload
* Focus on explanation over correctness

## If support is limited

* Design materials to be self-guided

---

# Tools

* Zoom (lectures + integration)
* LMS (Canvas/Google Classroom)
* Verilog simulator (CSUF)

---

# Final Advice

* Do not over-lecture
* Let students struggle (especially CSUF)
* Keep HS engaged with simple, visual tasks
* Focus on experience, not perfection
